Building VMT19937
=================

VMT19937 is a header-only library. To use it in your own project, simply add the
include/ directory to your include path - no build step is required.

Include Macros
--------------
When compiling against the headers, you can define the following macros:

  SIMD_N_BITS   Explicitly set SIMD width (128, 256, 512). If not defined,
                it is automatically detected based on compiler flags (e.g.,
                -mavx2, /arch:AVX2).
  SIMD_ISA      Explicitly set the target ISA (e.g., sse42, avx2, avx512vl).

Building is only necessary if you want to run the bundled executables:
  - test.exe    correctness tests
  - perf.exe    throughput benchmarks
  - demo.exe    usage examples
  - jump.exe    jump-ahead matrix utilities
  - encoder.exe matrix encoder utility

These require a C++20 compiler and GNU make.
Note: Windows' built-in nmake is NOT compatible - the Makefile uses GNU make syntax.

Jump matrices
-------------
The jump matrices are under the `dat/` folder. They are stored in compressed `.7z` format
to save space and **must be decompressed** before use.

Commonly used matrices are located in:

| Folder      | Generator    | Description                             |
|-------------|--------------|-----------------------------------------|
| `dat/mt32/` | MT19937-32   | Standard 32-bit Mersenne Twister        |
| `dat/mt64/` | MT19937-64   | 64-bit Mersenne Twister                 |
| `dat/sfmt/` | SFMT19937    | SIMD-oriented Fast Mersenne Twister     |

### Generating New Jump Matrices
If you need to build new jump matrices for $2^n$ jumps, use the `jump.exe` utility:

    # Example: Generate MT19937-32 matrices for 2^20000 jumps
    .\bin-128-cl\jump.exe -g=mt32 -t=20000

To build an arbitrary jump matrix for $J$ jumps:
1. Decompose $J$ into powers of 2 (binary representation).
2. Compute the necessary $2^n$ jump matrices using `jump.exe`.
3. Multiply the resulting matrices to get the final jump transformation.

Build System
------------
The project uses a GNU Makefile. Output binaries land in bin-<NBITS>-<compiler>/.

Makefile variables (all optional):

  NBITS         SIMD width: 128 (SSE4.2) / 256 (AVX2) / 512 (AVX-512).
                Default: native (-march=native) on GCC, 128 on MSVC.
  ISA           Instruction Set Architecture. Overrides auto-detection.
                Values: sse42, avx2, avx512vl (x86); neon, sve256 (ARM).
  CXX           C++ compiler. Default: g++. Pass CXX=cl for MSVC.
  MKLROOT       Path to Intel MKL root. Auto-discovered if not set (see MKL section).
  TESTU01_DIR   Path to TestU01 install. Default: ../testu01/install.

### Linux, Cygwin, MSYS2, or Git for Windows (GCC)

    make                        # NBITS defaults to native
    make NBITS=256

Binaries land in bin-128-g++/ and are native Windows executables.

### Windows (MSVC)

The build requires both cl.exe (from MSVC) and GNU make. Neither cmd nor PowerShell
ship with GNU make. Obtain it from one of:

  - Cygwin   - <cygwin-install>\bin\make.exe
  - Git for Windows - C:\Program Files\Git\usr\bin\make.exe  (present if Git is installed)
  - MSYS2    - C:\msys64\usr\bin\make.exe

vcvars64.bat is found under <VS-install>\VC\Auxiliary\Build\vcvars64.bat.
Activate the MSVC toolchain, then call the appropriate make.exe:

  From PowerShell (Cygwin make):
    cmd /c '"<path\to\vcvars64.bat>" && <cygwin>\bin\make.exe CXX=cl NBITS=128'

  From PowerShell (Git for Windows make):
    cmd /c '"<path\to\vcvars64.bat>" && "C:\Program Files\Git\usr\bin\make.exe" CXX=cl NBITS=128'

  From a VS Developer Command Prompt (cmd.exe), add make to PATH first, then:
    set PATH=<path\to\cygwin-or-make-dir>;%PATH%
    make CXX=cl NBITS=128

Binaries land in bin-128-cl/.

MKL (optional, perf.exe only)
------------------------------
MKL enables comparison benchmarks against Intel's reference MT19937 and SFMT19937.
The Makefile auto-discovers MKL in the following order:

  1. MKLROOT variable if set explicitly:
       make MKLROOT=/path/to/mkl CXX=cl NBITS=128

  2. mkl.h on the system INCLUDE path (set by vcvars or oneAPI environment scripts).

  3. vcpkg at <vcpkg-root>/installed/x64-windows (hard-coded Makefile fallback).

  4. /opt/intel/oneapi/mkl/latest (Linux default).

If MKL is not found, perf.exe is built without MKL benchmarks (no error).

At runtime, the MKL DLLs must be in PATH. With vcpkg:

    $env:PATH += ";<vcpkg-install>\x64-windows\bin"
    .\bin-128-cl\perf.exe --dir dat

With Intel oneAPI:

    $env:PATH += ";C:\Program Files (x86)\Intel\oneAPI\mkl\latest\redist\intel64"
    .\bin-128-cl\perf.exe --dir dat

Known Issues
------------
- testu01.exe is not buildable on Windows because the TestU01 static library must be
  compiled separately. All other targets (test, perf, demo, encoder, jump) build fine.
- MKL is not available in the Cygwin build. perf.exe will build and run without MKL
  benchmarks when using GCC/Cygwin on Windows.
